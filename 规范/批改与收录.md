# 批改与收录

## 1. 清点本批范围

保存本次实际可取得的原图到 `原始资料/<作业编号>/`，记录上传顺序和真实页码。图片只在聊天中可见且无法取到文件时，保留图号、题目位置以及无法保存的原因，图片路径设为 null。历史记录中的校验值保留；新记录不要求计算校验值，更不能猜写。

按每个可以独立批改的小题清点数量，并记录 `expected_question_count`。同一道开放题的几个答题要点仍属于一道题；阅读同一材料的不同小题分别建题。不要把旧错题摘录称为完整作业。

题目存在但无法确定是否必答、是否还有下一页答案时，记录范围或作答区域待核实。读不清的题至少保留原题号、位置和不可辨说明，批改结果用待核实，确保数量对得上。

完成条件：每张图片均有来源记录；本批所有题目均有题目记录或明确的待核实记录。

## 2. 分离识别结果与判断

- 题目、学生答案、老师批注分别转录。学生答案保留原来的错误、符号和断句；只有整理者转述时标为历史转述。
- 共享阅读全文、图形或表格与题目关联。缺失全文时不能依据文章名字补写原文。
- 知识点表示考查能力，错误类型表示可观察的错误。复用知识点目录中的固定编号及别名，章节可为 null。
- 题号使用真实原题号；没有原题号时标明系统编号。系统编号不冒充试卷题号。

完成条件：题干与学生答案来源清楚，无法辨认的位置明确，没有把参考解答填进学生答案。

## 3. 独立核验并完整批改

先独立求解再比较学生答案，数学复算、词数实际计数；主观题考虑等价表达。官方答案、老师批注、AI解答与历史记录分别标明依据。有争议时保留冲突，不把某一来源自动当成权威。

结果仅为：正确、部分正确、错误、未作答、待核实。

只有“必答 + 答案区域完整可见 + 确实空白”才确定未作答。多要点题答了一部分，记录部分正确和要点缺漏，不把整题称为没做。漏答原因未知时如实记录，不能推测为不会或懒惰。

每个错误写入 `grade.errors`：

- `error_type` 从 [错误分类](错误分类.json) 选择；没有合适类别时用待分类，并在备注提出分类需求。
- `error_reason` 引用原题关键信息或学生原句，具体说明差异和正确处理方式。
- `knowledge_point_ids`、`location`、`evidence` 标明知识点、位置和观察依据。
- `cause` 分为有证据支持、推测、未知。只有答案终值时通常不能定位心理原因；未知时 hypothesis=null。

一题可以有多个独立错误。同一处第三人称单数或过去式问题按直接违反的规则分类，避免重复计数。正确题 errors=[]；按题目数统计错题数量。

对实际检验的每个知识点与错误模式写 `assessments`，不能把整题结果复制给所有标签。漏答只证明未完成，不能自动证明各知识点都不会。核验不足的记录保留待核实，不提升掌握等级。

完成条件：每题都有结果；参考答案、关键推导、核验依据和不确定项齐全。原图清点数与记录数一致。

## 4. 保存批改并展示报告

直接在相应目录保存作业、材料、题目和作答 JSON，暂不创建错题条目。按 [数据操作](数据操作.md) 复核记录并编写报告。

用户首先看到 Markdown：整体情况 → 按页逐题结果 → 同页错题、部分正确题、空题和待核实题的解析 → 针对性建议与收录候选。

同一作业页码完整、唯一时按真实页码排序；否则按上传顺序并明确图号。跨页题主记录放在题干起始页，列明相关图片。正确题简列结果，复杂错题展开推导。建议和肯定都引用本次观察，简单错误不必写成长篇。

AI 根据本次记录编写报告和教学建议，保持原始数据与批改结论可追溯。收录候选表必须给出页码或图号、原题号和固定编号，避免跨页同号题混淆。

完成条件：报告覆盖所有已清点题目，用户能对照图片找到题目，候选清单包含原题号和固定编号。

## 5. 确认收录

用户明确选择后，映射到本批固定编号，再创建相应的错题 JSON。approval 保存实际确认原话和日期；“请批改”不等于“全部收录”。用户未选择时，停在候选清单。

支持全部、指定题和排除指定题。待核实题可以经用户选择收录，并继续保留状态。重复确认不会重复建卡。同题后续作答直接追加；新的错题仍需新确认。

完成条件：重新读取本次错题，核对集合与用户选择一致；更新索引和掌握报告；向用户说明实际收录范围。
