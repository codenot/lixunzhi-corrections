# 批改与收录

## 先区分对话批改与保存请求

“请批改作业”“看看这些题做得对不对”“批改这份练习”默认只在对话中完成。可以按需读取已有资料，但不新增、修改或删除仓库文件：不保存图片、不创建 JSON 或 Markdown 报告、不更新索引或掌握状态，也不为候选题预先创建记录。旧错题重做和已生成练习的批改遵守同一边界。

用户明确说“把这两题记录为错题”“收录第2、5题”“全部收录”且范围能够确定时，这句话就是收录确认；完成必要识别和核验后直接保存，无需再次询问。没有明确保存请求时，完成下面第1至4步即可，不要求用户必须选题。

“保存这次作答”“保存这份批改”“更新掌握情况”允许按相应范围保存作答证据及相关记录，但不等于收录新错题。仅要求保存报告时，只保存指定报告，不附带创建整套数据。用户一次要求“批改并记录指定错题”时，先完成批改，再按已明确的范围保存。

## 1. 在对话中清点本批范围

按图片上传顺序和真实页码定位题目，清点每个可以独立批改的小题。同一道开放题的几个答题要点仍属于一道题；阅读同一材料的不同小题分别计数。不要把旧错题摘录称为完整作业。

题目存在但无法确定是否必答、是否还有下一页答案时，说明范围或作答区域待核实。读不清的题至少保留原题号、位置和不可辨说明，批改结果用待核实，不能漏掉。

完成条件：本批每张图片均已检查，所有小题均纳入对话中的批改清单；不创建作业记录或保存原图。

## 2. 分离识别结果与判断

- 题目、学生答案、老师批注分别识别。学生答案保留原来的错误、符号和断句；只有整理者转述时标为历史转述。
- 结合相关阅读全文、图形或表格判断。缺失全文时不能依据文章名字补写原文。
- 知识点表示考查能力，错误类型表示可观察的错误。可按需参考已有名称；固定编号在保存时复用或创建，章节可为 null。
- 题号使用真实原题号；没有原题号时标明对话中的临时序号，不冒充试卷题号或持久记录编号。

完成条件：题干与学生答案来源清楚，无法辨认的位置明确，没有把参考解答填进学生答案。

## 3. 独立核验并完整批改

先独立求解再比较学生答案，数学复算、词数实际计数；主观题考虑等价表达。官方答案、老师批注、AI解答与历史记录分别标明依据。有争议时保留冲突，不把某一来源自动当成权威。

结果仅为：正确、部分正确、错误、未作答、待核实。

只有“必答 + 答案区域完整可见 + 确实空白”才确定未作答。多要点题答了一部分，记录部分正确和要点缺漏，不把整题称为没做。漏答原因未知时如实说明，不能推测为不会或懒惰。

每个错误都要说明类型、具体差异、位置、作答证据和正确处理方式；错误类型参考 [错误分类](错误分类.json)。没有合适类别时用待分类。原因分为有证据支持、推测、未知；只有答案终值时通常不能定位心理原因，不把猜测当事实。

一题可以有多个独立错误。同一处第三人称单数或过去式问题按直接违反的规则分类，避免重复计数；按题目数统计错题数量。只评价实际检验的知识点与错误模式，不能把整题结果复制给所有标签。漏答只证明未完成，不能自动证明各知识点都不会。

若用户随后要求保存，将这些判断按记录格式写入 grade.errors 和 assessments；正确题 errors=[]，原因未知时 cause.hypothesis=null。纯批改阶段直接在对话中解释，不要求输出或保存 JSON。

完成条件：每题都有结果；参考答案、关键推导、核验依据和不确定项齐全。对话中的逐题结果数与清点数量一致，仓库不变。

## 4. 在对话中展示批改结果

按以下顺序直接回复：整体情况 → 按页逐题结果 → 同页错题、部分正确题、空题和待核实题的解析 → 针对性建议与可收录候选。此处使用对话中的 Markdown 排版，不创建报告文件。

同一作业页码完整、唯一时按真实页码排序；否则按上传顺序并明确图号。跨页题放在题干起始页，列明相关图片。正确题简列结果，复杂错题展开推导。建议和肯定都引用本次观察，简单错误不必写成长篇。

候选清单给出页码或图号、原题号和必要的位置描述；没有原题号时用明确标注的临时序号。已有题目可引用原固定编号，新题不提前分配固定编号。待核实项单独说明，不能把它们直接断言为错题。

完成条件：对话覆盖所有已清点题目，用户能对照图片找到题目；不保存图片、题目、作答、批改报告，也不更新索引和掌握情况。

## 5. 用户明确要求记录后再保存

先根据用户原话确定保存和收录范围。支持全部候选、指定题和排除指定题；“全部”指向不清时才澄清。明确指向题目的“记录错题”已经是确认，不另设一轮确认。待核实题可以经用户选择收录，并继续保留状态；已确认正确的题不作为错题收录。

按 [数据操作](数据操作.md) 读取索引和相关原记录，检查重复，复用或建立固定编号。只为选中的题目保存必要的作业、共享材料、题目、作答、知识点和错题记录，不把对话中批改过的其他题目顺带落库。没有进行过对话批改的选中题，先完成同样的识别和核验，不扩大到未指定题目。

仅保存部分题时，作业 coverage 使用指定范围，expected_question_count 为该作业当前已保存范围内的小题数，scope_note 说明实际保存范围以及已知的原作业范围；不能因为对话中批改过整份作业，就声称仓库保存了整份作业。已有作业增补题目时复用作业记录，并同步范围和数量。

保存本次选中题及必要材料所依赖、且实际可取得的原图到 `原始资料/<作业编号>/`，记录上传顺序和真实页码。可以保留含选中题的整页原图作为来源，不因此为同页其他题建立记录。图片只在聊天中可见且无法取到文件时，保留图号、题目位置以及无法保存的原因，图片路径设为 null。历史校验值保留；新记录不要求计算校验值，更不能猜写。

mistake.approval 保存实际确认原话和日期。重复确认不会重复建卡或重复保存同一次作答；同题后续实际作答在明确要求保存时追加，新的错题仍需明确收录。若后续已无法取得原图或完整学生作答，如实标明缺失，不根据先前摘要补造。

完成条件：重新读取本次保存内容，核对题目、作答与错题集合符合用户范围；更新相关索引、分科掌握报告及总览，并在对话中说明实际收录范围。收录默认不另建整份作业的批改报告文件。
