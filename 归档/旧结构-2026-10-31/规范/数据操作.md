# AI 直接维护记录

本项目由 AI 在用户明确要求记录、保存、修订或更新时直接读写文件。遵循 [记录格式](记录格式.md) 和 [记录示例](../模板/记录示例.json)，无需导入包、专用命令或程序运行环境。

## 写入触发与范围

普通作业、练习和旧错题重做的批改默认只在对话中完成，不保存图片、JSON 或报告文件，不修改已有记录、索引或掌握状态。总结和只读检查也不自动修复文件；发现不一致时先在对话中说明。

- “把这两题记录为错题”“收录第2、5题”等指向明确的请求，即为收录确认，只保存选中题及必要关联记录，不再次询问。
- “保存这次作答”“保存这份批改”“更新掌握情况”允许按明确范围保存所需题目、作答与来源，包括用于掌握判断的正确作答；不自动收录新错题。
- 仅要求保存一份报告时，只创建或更新指定报告；不附带创建结构化记录、保存原图或更新索引。报告注明依据与范围。
- 生成练习按出题规范保存练习及相关资料；不因出题而创建学生作答或收录新错题。

以下结构化记录操作和索引同步仅适用于已经明确要求的保存范围，不能以复核、同步或准备收录为由扩大写入。

## 保存前先查现有记录

1. 读取 `数据/索引.json` 和本次相关的知识点、题目及作答。索引仅用于定位，具体事实回到原记录核对。
2. 根据原图、页码、原题号和内容判断是否已记录。同一图片重复发送时复用原题；新的实际作答另存一次。只因题目相似，不合并不同作业。
3. 在同一科目内复用已有知识点及别名；不同科目的同名知识点使用各自编号。新编号可以用“类型前缀-日期-序号”，例如 `q-20261030-001`；先检查是否占用。旧编号保持不变。

完成条件：明确哪些记录需要新增、哪些只是引用或追加作答，没有重复建题或重复命名知识点。

## 按明确范围保存与收录

- 先从用户原话和对话中的图号、页码、题号确定范围，再复用或创建固定编号。对话临时序号不等于持久记录编号。
- 收录错题时，只保存选中题及其必要的 assignment、material、question、attempt、knowledge 和 mistake；已有记录复用，每条新增记录一个 JSON 文件，文件名与 id 相同。不顺带保存同批其他题目。
- 只保存部分题时，新作业 coverage=指定范围，expected_question_count 为该作业当前已保存范围的小题数，scope_note 说明具体范围；已有作业增加题目时同步范围和数量。整份作业仅用于确实保存了全体小题的情况。聊天批改数量与仓库保存数量分开核对。
- 保存范围内每个可独立批改的小题都有记录，待核实题也保留具体疑点。不能把范围外的未保存题当作漏记，也不能把聊天中的整份批改范围当作保存范围。
- 仅保存选中题及必要材料所依赖、实际可取得的原图；无法保存时，image_path=null 并说明原因。整页来源图包含其他题目不代表收录或保存这些题。
- mistake.approval 保存实际确认原话和日期。重复确认不重复建卡，也不重复保存同一次作答；同一原题只保留一个错题条目。明确要求保存后续实际作答时追加 attempt；练习中的新题若需进入错题本，仍需明确收录。
- 保存后重新读取文件，逐题核对题面、原答案、参考答案和错误说明，更新相关索引及分科掌握报告、总览，并在对话中说明实际结果。默认不另建整份作业的批改报告，用户要求保存该报告时再生成。

“请批改”“请解释”“请出题”均不代表同意收录。题目已确认正确时，不把它作为错题；原收录结论后来被纠正为正确，在用户要求保存更正后保留历史条目并注明更正，从当前待练错题中排除。

完成条件：授权保存范围内所有题目均有结果，正式收录集合与用户确认范围一致；范围外的题目只保留在对话中。若原图或完整学生作答已不可取得，说明缺失，不用聊天摘要补造原始答案。

## 追加作答和更正

**新一次真实作答**：新增 attempt.id 和 submission_id，保存新的原答案及日期。独立性没有证据时填未知。

**同一次作答的评分更正**：新增 attempt，supersedes_attempt_id 指向当前有效批改；保留 question_id、submission_id、submitted_at、student_answer，填写更正原因和记录日期。旧批改保留，更正链只有一个末端，不能产生分叉或循环。统计使用链末端。

**补充材料、修正题面或参考答案**：

1. 先在 `数据/修订/` 保存 revision 记录，包含目标编号、修改日期、原因、依据以及完整的 previous / updated 快照；有前次修订则关联 previous_revision_id。
2. 保持题目和来源身份不变，更新相应资料。题目或材料的 `revision` 加一；影响批改的题面、条件、参考答案、目标变动都算修订。
3. 找出依赖这些资料的作答，比较其 based_on 版本。版本不一致的旧批改在索引和报告中标为待重新核验，暂停作为掌握证据；保留旧作答原文。
4. 核实学生答案后追加批改更正，记录当前版本，再更新相关掌握情况。不能仅因参考答案改了就自动重判学生作答。

完成条件：旧内容可追溯，新旧版本明确，受影响的旧结论不再被当成当前有效证据。

## 总结和出题

总结时按 [出题与掌握](出题与掌握.md) 读取相关原题与有效作答，在对话中说明结论，不自动更新索引或报告。用户要求生成练习时，直接编写练习及其记录，每道题保留来源错题、检验目标和题型层次。

学生卷和答案卷分别写入 `练习/`。学生卷仅含题面、必要材料、题目编号和作答要求；答案、错误类型、解题提示和来源错因留在答案卷及内部记录。保存后从学生视角通读一遍。

## 更新索引与报告

在完成已明确要求的结构化记录写入后，更新 `数据/索引.json`，保留现有结构和每条索引记录的 subject。题目与知识点以各自的 subject 为科目依据；作答和错题通过 question_id 归属科目，不重复保存主要记录。

- mistake_count、subject_counts：按实际错题条目统计，不按错误标签或练习数量统计。
- mistakes：更新原题表现、关联作答及来源。source_verification 与 source_verification_note 单列原题核实状态及原因，verification 继续表示批改核验状态；题面完整性仍由 content_status 表示。仅当原题和必要材料已实际核对时，才把 source_verification 标为已核实。
- patterns：按科目＋知识点编号＋错误类型整理证据；记录有效作答编号、日期、事件和掌握状态。尚无足够有效作答时显示掌握情况待验证，与原题或批改的待核实分开。
- knowledge：在本科目内汇总已观察的错误模式，采用保守状态，注明不代表知识点的全部能力。

掌握报告分别保存在 `报告/语文/错题与掌握情况.md`、`报告/数学/错题与掌握情况.md`、`报告/英语/错题与掌握情况.md`。各科报告只包含本科目的知识点、错误模式、原题表现、作答依据和核实状态。`报告/错题与掌握情况.md` 作为总览，仅汇总各科题数并链接分科报告，不设置跨科总掌握等级。

只将已明确要求保存且实际落库的有效作答用于持久掌握状态；纯对话中的新作答不会自动进入索引和报告。先确认有效证据，再计算状态。不能直接把上次的“初步掌握”作为本次事实沿用；原题改编号、同题重复作答不能算两道不同变式。状态变化遵循出题与掌握规范。

优先重算本次涉及的科目、题目与知识点，更新对应分科报告及总览题数。核对各科题数之和等于总题数，各科报告与索引中该科目的记录集合一致。若索引和原始记录不一致，根据原始记录修正索引；历史批改报告保留当时内容，必要时附更正说明。

## 写入后的复核清单

重新读取本次新增或修改的文件，逐项确认：

1. JSON 格式完整，编号唯一且与文件名一致，所有引用都能找到。
2. 授权保存范围内的来源和题目均有记录，作业题目数与已保存范围一致；对话中批改但未要求保存的题目没有顺带落库。仅在要求保存批改报告时核对其逐题范围和同页聚拢。
3. 正确题 errors 为空；错误、部分正确、漏答有对应证据；不确定项保持待核实。
4. 确定漏答必须是必答、作答区域完整可见且确实空白。
5. 新增错题均有用户确认记录；重复确认没有重复建卡。
6. 错因推测与已观察事实分开；确定归因有依据。
7. 更正链和资料版本清楚，旧版及存疑批改没有提升掌握等级。
8. 学生卷没有泄露答案或提示，索引和报告与主要记录一致；掌握记录的题目、知识点和作答证据属于同一科目，各科报告没有混入其他科目。

完成后简要说明实际保存和收录范围、需要用户补充的材料。这里是 AI 逐项复核，不声称存在程序强制保证。
